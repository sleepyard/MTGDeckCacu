## 结论

V2 过早把“Shrine 各一张”当成结构结论，导致检索偏向单张工具箱，漏掉了以重复低费 Shrine 提高 `United Battlefront` 密度的路线。`Setessan Champion` 也只提供慢速持续抓牌，没有进入战场 / 坟场 / 闪烁三条新轴的交集，应移除。

本轮另确认 `Dance of the Manse` 在 Arena 可用。之前的平台不可用结论是假阴性；运行记录没有保存足够的错误响应，无法唯一确定是 HTTP 400、精确名过滤还是空结果误判，但机器门禁不应把任何请求失败转换成“平台不可用”。

## 新发现

### P0：行侣不是普通备牌标签

- 行侣有自己的构筑条件、赛前展示区与每局一次 `{3}` 入手规则。
- 在 BO3 构筑赛中它占一个备牌位置；约力昂方案因此是 80 主牌 + 1 行侣 + 14 普通备牌，而不是 80/15 再额外附送一张。
- 抽牌概率不能把行侣算进牌库；资源分析要把它记为“确定可访问、需先付 `{3}` 入手、再正常施放”的外部资源。
- 换备后每一局的 starting deck 仍必须满足条件。约力昂至少 80 张的要求意味着所有换备方案需要维持 80 张以上。

### P0：候选密度必须相对目标牌文本计算

- Battlefront 只命中非生物、非地、法术力值不高于 3 的永久物。Go-Shintai 虽是 Shrine，却是生物，不能命中。
- Jukai 降费与 Leyline Binding 的 domain 只改变支付，不改变法术力值。
- 计算“Shrine 数量”不能替代“Battlefront 合法命中数”。本轮分别得到 A 25/60 与 C 32/80，并计算顶七至少双命中概率。

### P0：平台请求失败与真实零结果必须分型

- `Dance of the Manse` 的 ELD 印刷有 Arena ID，但上轮候选判断错误。
- HTTP 失败、查询 DSL 失败、分页未完成、模糊名未精确命中和真实零印刷必须是五种不同状态。
- 只有成功遍历全部印刷且零平台印刷，才能输出“平台不可用”。

### P1：传奇重复数需要按功能分层

- 传奇规则不等于只能放一张。重复数影响自然抽取、Battlefront 命中和被磨入坟场的密度。
- 有 ETB 的传奇 Shrine 即使同时进场后因传奇规则牺牲一张，进场触发仍已产生；无 ETB 的重复 Sanctum 同时进场则通常浪费。
- 优化器需要分别记录 `draw redundancy`、`coexistence cap`、`ETB value before legend rule` 与 `discard / graveyard value`。

### P1：生命成本色源需要独立预算

- V2 有 Mana Confluence x4、Starting Town x3、Thran Portal x2，另有 Brushland x2；“可产任意色 / 对色”不能掩盖它们的直接生命成本。
- 色源评分需要输出预期启用次数与生命成本，而不是只计有色源数量。
- V3 使用 pathway、fast/slow land、triome、Fabled 与基本地，把直接扣血地产色降为 0；代价是更多选择锁定和横置时序。

## 工作流增量

1. 阶段 0 增加行侣策略参数：禁用 / 候选 / 强制指定。

6. 平台验证状态机禁止把请求失败 / 不完整分页降级为真实不可用。
