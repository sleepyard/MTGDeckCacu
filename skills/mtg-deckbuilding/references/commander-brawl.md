# Commander 与 Arena Brawl 配套交付

从仓库根目录执行。适用于 EDH 桌规沟通、Commander 构筑，以及线下牌表配一份 Arena 练习版；普通构筑和限制赛仍使用各自档案。

## 范围与约束

把用户已给的主将、预算、桌规、平台和玩法写入任务备忘；已有授权和约定继续有效。信息足以形成初稿时先完成可审阅牌表，只询问真正影响构筑的缺项。

“B桌”等本地称呼不对应固定官方等级。分别记录当前官方禁牌、Game Changers 主宰牌上限，以及用户对获胜速度、无限、额外回合、土地限制的约定。零主宰牌是名单约束，不能单独推导中等强度。只有用户要求时才限制为零；不要把某次牌表的限制变成通用默认。

每次查询现行名单，保存来源、查询日、内容哈希与版本/生效日；文档不要固化名单数量。可以用 `is:gamechanger` 召回，并和官方 Commander 页面核对；双面牌按 Oracle 身份或已验证的正面别名匹配。未知或过期名单不应被当作零命中。

## 分别建立赛制档案

| 项目 | 线下 Commander | MTGA 普通100张 Brawl |
|---|---|---|
| 分区 | 通常1主将加99牌库；多主将/行侣另验 | 通常1主将加99牌库；特殊主将/行侣条件另验 |
| 平台证据 | 已发行纸质印刷 | 已发行且客户端可用的 Arena 印刷 |
| 单卡 | 基本地和牌面张数例外以外限一张 | 按同一原则及当前客户端档案核验 |
| 颜色身份 | 所有面、规则文字及颜色标志 | 同左；另查重平衡版本 |
| 常见对局 | 四人、40血、21点同主将战斗伤害 | 双人、25血，无21点主将伤害规则 |
| 禁牌 | 当前 Commander 禁牌表 | 当前普通 Brawl 禁牌；不借用 Historic/Competitive Brawl |

表中是配套交付常见档案，不覆盖所有主将资格与牌面特例。身份、可组合的多主将、行侣和新牌型资格查询现行规则，不能用固定传奇生物字符串替代完整裁定。Arena 与纸质 CR 中同名 Brawl 变体的牌数可能不同，以目标客户端队列和官方说明为准。

## 查询、构筑与版本对照

1. 中文主将先落到唯一英文/Oracle 身份。用 `mtg_tool.py check` 分别检查 Commander 与 Brawl；纸质检查不附 Arena 条件。
2. 候选按目标赛制、颜色身份、查询日和平台过滤。Arena 配套版以已验证的印刷为证据，不凭最新印刷的 `games` 一票否决。
3. 读完整 Oracle 和全部 `card_faces`。主题引擎区分施放、进场、合变、攻击与战斗伤害；类型条件区分非人类等具体限制。涉及交互时按 `skills/mtg-rules/SKILL.md` 查规则。
4. 配套版尽量保留用户主轴，并输出按数量守恒的增减对照。区分平台不可用、赛制禁牌、规则差异和双人节奏调整；这些不是预算替换或备牌。
5. 用 `deck_version.py` 生成各自版本的 TXT/MD，按主流程完成逐牌定位、打法、费用与 PNG。分支可共用一个主题目录，不能覆盖旧版。
6. 交付前按 `skills/mtg-guide-review/SKILL.md` 核对全文。登记事实通过只代表登记范围；另记机器检查、语义审阅、客户端导入与真人实战的各自状态。

同名牌按 Oracle 去重及统计，但保留实际通过平台检查的印刷。`digital: true` 可能表示 Arena 再录印刷，不等于纯数字设计；不要据此排除一张已有纸质原版的牌。重平衡 `A-` 版本则必须独立核对规则文本与合法性。

## 当前工具边界与命令

```powershell
# 纸质单卡合法性；省略平台参数不要求 Arena 收录
python tools/mtg_tool.py check "Brokkos, Apex of Forever" --format commander

# Arena 单卡和牌表检查；仍需补充下面的 Commander-style 门禁
python tools/mtg_tool.py check "Brokkos, Apex of Forever" --format brawl --platform arena
python tools/mtg_tool.py validate arena.txt --format brawl --colors bug --no-sideboard

# 独立规则证据与指南登记事实
python tools/mtg_rules_tool.py rulings "Brokkos, Apex of Forever" --json
python tools/mtg_guide_audit.py arena.txt arena.md --claims arena.claims.json --out arena.guide_audit.json
python tools/cn_audit.py check arena.md
```

`mtg_tool.py validate` 当前仍使用普通构筑数量与四张上限，默认平台为 Arena；`deck_version.py` 也只有基础门禁。二者单独通过不证明 Commander/Brawl 完整合法。没有 `--platform paper` 这个参数，不要编造命令。纸质场景可复用 `check`/底层查询并另做结构审计。

结构审计至少检查：真实分区和总数、主将资格与组合条件、单卡及牌面张数例外、所有面颜色身份、已发售平台印刷、目标禁牌与桌规名单。使用 `deck_model` 解析，不再写另一套文本解析器。输出明确说明范围和未覆盖的牌面特例；失败项与证据缺失分开。

本次案例的自定义审计只支持一个指定主将、99张牌库、无备牌/行侣；其中基本地以外一律限一张，未泛化“任意张数”牌、多主将、可互换牌名、特殊主将资格或行侣。不要直接改个路径就宣称适用所有 EDH。

## 法术力与造价

主将是确定可访问资源，不进入自然抽牌概率母体。地牌卡位、可当地的 MDFC、加权地当量、找地到手和加速分别统计。双符号需求独立计算；通路不能同时支付两种颜色，依赖对手的地不算无条件色源。

静态色源抽样若忽略横置、通路选面、目标消耗或加速，应称为模型估计并说明方向，不能默认叫严格上下界、准时施放率或击杀回合。双人先手少抓牌与多人抓牌规则按目标对局分别建模。

`tools/newbie/deck_cost.py` 当前 `census` 只计 `main`。配套 Arena 成本需要按同一指标另补计 `Commander`，并核对已发行 Arena 印刷的最低可用稀有度。纸质版有未收录牌时，部分 Arena 签名既不是完整野卡成本，也不是实体市场价格。不要因为未识别而计零，或把用户无上限预算套进标准新手预算档。

## 证据、缓存与复现

把本次实际输入、配置、TXT哈希、规则/名单来源、平台印刷、逐项结论留在 `AuditReport/` 或套牌目录；这些是本地产物，不自动进入 Git。最终可复用规范写入本技能/主流程，通用实现才进入 `tools/`。

研究脚本按文件存在复用缓存时，修改查询、候选或日期不会自动失效。更换输入需换研究目录或核验查询/输入哈希，不能把旧批次与新名单拼接成“最新证据”。最终回执应关联具体输入的内容哈希。

同一主机不要并行风暴式请求 MTGCH 翻译。优先按系列批量查询；429或超时记录为失败，不能变成没有中文名/不合法。官方 HTML 中名单可能在脚本数据内；解析不到不等于空名单，应和另一来源比对后再下结论。
