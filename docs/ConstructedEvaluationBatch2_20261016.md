# 构筑与评测：第二批交付

日期：2026-10-16。范围为固定构筑约束、主题协同排序、网页评测和版本对照；Alchemy继续排除。沿用现有Python标准库工具和单份工作台牌表状态。

## 固定牌张与协同排序

`constructed_strategy.py`保留种子文件中的主牌、备牌、指挥官、行侣及其数量，先预留指定备牌占用的同名额度，再填主牌。重复种子行合并检查需求；主备合计超限、备牌加行侣超过15、指定牌不合法或超出种子色组时明确失败。BO1保留显式指定的备牌，不自动补满；BO3在指定备牌基础上补候选。行侣条件、完整赛制特例和换备后的合规仍须单独核验。

网页「指定牌张数量与主备分区」接收与CLI种子文件相同的文本；`POST /api/seed-constructed`增加可选`seed_text`，填写后优先于旧`seeds`牌名数组。例如：

```json
{
  "candidates": ["此处替换为检索导出的完整牌面对象"],
  "format": "pioneer",
  "bo3": true,
  "seed_text": "Deck\n4 Core Card\n\nSideboard\n2 Side Card"
}
```

上例仅说明请求结构，牌名与候选须替换为实际检索数据。

`constructed_synergy.py`提供纯函数启发式：识别合变、衍生物、+1/+1指示物、自身坟场、咒语类别、神器、回血和显式部族回报，将资源/动作与回报连接。仅共享生物类别不加分；只奖赏瞬间的牌不会因法术得到该项加分。每类信号加0.75，总加分上限2，保持原有模块配额与节奏排序；理由附相关牌名，网页可展开查看逐牌依据。

这不是Oracle语义解析器，未覆盖所有句式、时序、目标限制和牌面特例。协同分不证明配合成立、组合技可用或胜率提升；具体线路继续由规则/Spellbook工具及人工审阅确认。

## 网页评测

启动`python tools/deck_workbench.py serve`，打开`http://127.0.0.1:8644/`，进入「核验 → 展开与版本评测」：

1. 选赛制、抽样次数、观测回合和首回合是否抓牌；关键咒语每行一个英文牌名，留空自动选择。
2. 可保存当前牌表作对照，然后修改当前牌表；也可粘贴旧版本。对照输入不替换工作台牌表。
3. 运行评测后查看起手可留比例、各回合土地支付潜力、抽到且可支付比例、95%抽样区间，以及最后观测回合的版本差值。结果可下载为完整JSON。

默认复用候选/牌池中的牌面，缺失牌名通过已有缓存HTTP传输精确补查。可提供离线Scryfall/search JSON数组；一旦提供则仅使用该数组及自动补全的基本地，缺牌报错，不偷偷补查。未知色源、MDFC或费用以`partial`及具体原因展示，不伪装成完整覆盖。

`workbench_evaluation.py`负责请求校验与牌面准备，`deck_evaluate.py`继续负责纯计算。接口为`POST /api/evaluation/start`，返回202与`job_id`；随后`GET /api/jobs/<job_id>`查询进度、结果和失败原因。

```json
{
  "format": "pioneer",
  "runs": 2000,
  "turns": 5,
  "on_draw": false,
  "targets": ["Exact Mainboard Spell Name"],
  "baseline_text": ""
}
```

API还接受`seed`、`max_mulligans`、`free_mulligans`、`keep_min`、`keep_max`和离线`cards`数组；未知键和错误类型拒绝。网页任务限1–5000次抽样、1–8回合、最多12种目标、两份牌表合计最多150种牌名。默认最多2次调度，留2–5地，Brawl家族/Commander免费1次；Commander默认首回合抓牌，可显式覆盖。赛制字段是上下文和默认参数来源，不执行合法性检查。

牌表、牌面与设置在提交时冻结；比较两版使用同一牌面快照和设置。相同输入的运行中请求复用任务，不同输入不覆盖正在运行的任务。运行期间改牌/改牌面会标记`stale`，旧结果不写回新牌表的评测槽位；后续编辑清除已缓存结果。失败与零概率分开。

模型仍为第一批的静态土地支付潜力模型，忽略横置时序、下地顺序、生命支付、非地加速、额外抓牌、咒语效果和对手；没有模拟MTGA BO1平滑。`complete`只指模型范围内完成。版本差值是描述性比较，区间只衡量抽样误差，不自动作显著性判断。
